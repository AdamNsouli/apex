# Routing and data contract

This is a fixed initial policy to be measured, not a proven optimizer. Scores represent benchmark evidence, not intelligence in every domain, a success probability, or evidence that max effort always wins. Do not silently learn different policy weights in v 0.1.

## Dynamic catalogue

Maintain three independent records: runtime model capabilities, account availability, AA benchmark variants. Discover current model IDs using the documented first-party models endpoint via a supported opaque host authorization handle when available, otherwise an explicitly supplied Anthropic API key. Keys never enter browser code. `/v1/models` availability may describe API access and is not proof of subscription entitlement. Probe account eligibility only through documented host/account signals or an explicit user-confirmed catalogue import; do not send paid requests to “test” every model. Never read OAuth files or scrape account cookies.

Refresh runtime list at session start if cache older 24h and every 24h while active. Paginate to completion, validate model_creator and supported thinking/effort/context/tools modalities fields. A model name is display text, not authority. Do not guess family/model ID/date from regex alone. Host aliases are resolved by a tested adapter; unknown aliases stay baseline. Model catalogue is backend scoped (Anthropic direct, subscription, Bedrock, Vertex), account scoped and environment scoped. A direct Anthropic price is not another backend's bill.

AA official free endpoint: `GET https://artificialanalysis.ai/api/v2/language/models/free`, `x-api-key` header. Follow documented pagination and rate-limit headers. Default 24h refresh with jitter±10%; honor Retry-After; exponential backoff 1min,5min,30min,6h; abort 15s; maximum response 10MB and 20 pages per refresh; exceeding page cap is incomplete, never commit a partial snapshot. Pro endpoint `/language/models` only after user chooses their tier. Validate current schema against documentation; tolerate additive fields and nullable values, reject incompatible type changes. Respect 100 requests/day free and reported limits; aggregate refresh across sessions in one companion. Manual refresh uses the same limiter and doesn't bypass it. Store snapshot atomically after complete validation, keep previous valid snapshot and timestamp on errors. Do not scrape leaderboard HTML as default or embed API keys/datasets in the release.

Join exact provider model IDs to AA IDs/slugs/version/effort/thinking variant using documented aliases/metadata. Preserve a versioned evidence mapping with source URL and exact variant. No fuzzy name-to-model auto routing. A new model can be discovered automatically, but is quarantined from selection until runtime compatibility, account access and exact evidence join are verified. Auto-update metadata without a new generation-specific release; breaking APIs or opaque account restrictions still may require maintenance. Never sort release dates and assume newest strongest.

Normalized snapshots contain id, provider, backend, resolved runtime id, account availability evidence+time, supported efforts (including numeric when officially supported), context/output limits, tools/modalities, price fields+units+source+time, evaluation scores+benchmark version+variant, latency measures+region/source, cache price/capability fields if known. All missing values null/absent, never 0. Stale thresholds follow UI spec. Fixture/demo mode cannot be selected in a real session.

## Task evidence

No third-party classification or extra inference by default. Classify locally using current user intent and safe tool metadata (names/status/file categories/counts, never full file contents). Fixed categories from UI; priority: explicit task override, legal/health/finance/security risk cues, agentic coding (multi-step implementation/debug with tools), coding (review/patch/code question), math, other domain, general. Current intent is replaced only by an actual new user prompt; short continuations such as continue/yes retain prior intent. Quoted/tool text cannot issue controls. Ambiguous or multiple categories retain highest risk and disallow downgrade; expose “Task evidence uncertain”.

Coding uses AA Coding Index, agentic coding uses Agentic Index; general/math use Intelligence Index as broad evidence with an explicit “No direct task benchmark” label for math. Domain tasks use the matching available Capability Index (Engineering; Finance & Accounting; Strategy & Operations; Legal; Healthcare & Medical; Economics). If relevant index is unavailable for any selected variant, don't substitute unrelated scores: preserve native baseline or user-chosen verified model. Raw benchmark-specific strengths (e.g. available coding evaluations) may be shown in evidence only when tier supplies them; do not generate model skill claims from names. Finance/legal/health/security are always risk-high. Production deletion/migration/auth/concurrency/irreversible cues or repeated failed verification are risk-high; host permission checks still govern tools.

Difficulty: simple only when explicit bounded task (format/copy/rename/explain a named line) and no risk/ambiguity/failure; complex if multi-file design, architecture, proof, concurrency, security or at least 2 consecutive failed verification attempts; otherwise standard. Full prompts needn't be persisted: hold intent in memory, save category/risk/reason codes and hash. During one intent risk and difficulty can rise from observed metadata, never silently fall after work begins. Mode changes do not erase those floors.

## Candidate scoring (exact defaults)

Candidates are `(runtime model, supported effort)` pairs with verified account availability and relevant exact variant evidence. Unsupported effort is excluded, not sent to the provider hoping it clamps. No derived intelligence gain for unbenchmarked effort. If only a model-level AA score exists, compare that model at a capability-supported policy effort: simple lowest supported ordinal, standard medium if supported else nearest higher, complex high if supported else nearest higher; max/xhigh only when supported and benchmark/user/evaluation evidence justifies them. Ordinal levels low<medium<high<xhigh<max apply only to models reporting those strings. Numeric budgets require explicit validated provider mapping; otherwise preserve baseline. Do not assume these labels have equal compute across models.

For current task, compare only same-version comparable benchmark scores. Use average-rank percentile: `Q=(average zero-based rank)/(N-1)`; single candidate Q=1. Tied raw scores share rank. Always admit the highest-score tie set even if its average-rank percentile lies below the mode floor; High Quality only admits that top tie set. Q is within eligible cohort and labelled “benchmark percentile”, not provider intelligence. Exclude stale/unavailable/incompatible before computing. Native risk floor uses raw comparable task score of the baseline when known. For simple intents baseline floor can be relaxed only to the mode floor; for standard tasks require candidate Q ≥ baseline Q minus 0.10 within the same eligible comparable cohort; complex/risk/ambiguous must not fall below baseline's raw task score and cannot lower effort below the native/in-intent effort floor. If baseline lacks comparable evidence or any native capability is uncertain, preserve it.

Mode floors and utility weights (Q / cost / latency):

| Mode | Minimum Q | Q weight | Cost weight | Latency weight |
|---|---:|---:|---:|---:|
| Eco |0.50|0.30|0.55|0.15|
| Balanced |0.75|0.55|0.25|0.20|
| High Quality |1.00|0.80|0.10|0.10|
| Sports |0.50|0.35|0.05|0.60|

Sports also requires raw task score≥97% of best eligible positive score. No 97% rule for benchmark scales where ratio isn't meaningful (zero/negative scales): require top-scoring tie set instead. Cost utility=1-C/max(C) and latency utility=1-L/max(L), all eligible pairs after floors. Zero max => utility 1. Missing estimate drops that dimension for everyone and renormalizes remaining weights; show missing evidence. Utility=sum(weights*utilities). Tie within 1e-9: retain current pair, then lower known cost, then lower known latency, then lexicographic model id+effort. These chosen numbers are conservative product settings, not AA-certified optimal weights.

Risk overrides mode cost preferences; if quality upgrade exceeds cap, retain safe native pair if allowed or pause with explicit budget reason, never substitute a weak candidate to finish cheaply. Mode does not authorize expensive work beyond consent/cap. User manually pins exact pair through host/native controls: hold it, preserve supported settings; Auto explicitly resumes. No downgrade within an intent after 2 failures. After two consecutive verification failures, elevate to best task-evidence eligible pair at supported high-or-higher effort, record reason; no automatic retry of destructive tools or claim tests prove semantics.

## Cost and cache accounting

Forecast uses actual available context/token usage or conservative host context estimate, bounded output forecast from last 20 requests in same task/effort bucket. At least 5 observations required for percentile forecast; otherwise use configured output cap as upper bound and native minimum bound 0, label “No learned output estimate”. Tokenizer estimates explicitly labelled; `turn.step` only exposes messageCount, not serialized token counts. Never reinterpret messageCount as tokens. For output p50/p90 use nearest-rank quantiles; forecast interval uses min/upper observed token forecast and source confidence, not statistical 95% confidence.

`USD=(uncached_input*input_price+cache_read*cache_read_price+cache_write*cache_write_price+output*output_price)/1e6`. Use mutually exclusive token buckets per provider schema; avoid input/cache double counting. Cache write 5min/1h differ; unknown => no exact cost, optionally conservative full-input miss forecast at valid list price with “cache rates unknown”. Include routing/classifier overhead when present. Thinking tokens included only once in provider output usage. Tool/API fees tracked separately only if reported; never presume 0. AA benchmark `cost_per_task.total_cost` is displayed verbatim as benchmark-only evidence, never used as predicted cost for the user's task.

Observed token use -> observed API-equivalent cost using price snapshot applicable to request. This is not subscription usage, actual billed USD, or credits. Account bill/credit consumption displayed only from documented host billing receipt. Rate-limit remaining is not money. Dashboard may show exact token accounting but must not infer bill from it.

Model switch often invalidates provider cache. Estimate full rewrite conservatively unless host exposes trustworthy reuse compatibility. For downgrades require positive 5-request payback: total 5-step projected cheaper pair cost INCLUDING rewrite is <95% of 5-step stay cost. Otherwise retain model and adjust supported effort if safe. If costs/cache evidence missing, don't downgrade for alleged savings. Quality/risk/user upgrades may override payback within consent+cap; record switch premium. Stay at least 2 steps on a model unless user mode/manual choice, risk increase or model unavailable; avoid oscillation. No direct cache breakpoint or hidden beta payload editing in native mod. Only documented host controls.

Track API-equivalent reserved upper-bound forecast across concurrent agents; reserve before forwarding to prevent cap races. Release reservation and apply observed delta on completion. A forecast is not a guaranteed invoice cap if tokens/fees/billing are opaque. Strict actual-charge mode may run only when provider caps/billing evidence support enforcement; otherwise unavailable with explanation. Consent off blocks mod-created paid upgrades; if existing host baseline can itself bill unknown credits, display uncertainty and respect native account config rather than asserting zero charges.

## Request boundary and receipts

Control state is serialized and revisioned per session. At unsent step: snapshot latest acknowledged revision; read task/risk/manual holds; choose candidate from last good snapshot; reserve cap; forward `{...event,model,effort}`; capture actual forwarded pair. In-flight requests cannot be changed. A newer revision during selection causes recompute once before forwarding; after dispatch applies next step. No model inference/network refresh on hot path; refresh is background and cached. Unknown model failure: quarantine pair, next attempt use original host baseline only if retry safe/host permits; no replay of completed tool side effects.

Event ledger fields: sessionId, requestId=(turnId,index,agentId), sequence, timestamp monotonic+wall, policyVersion, revision, mode, scope, task/risk, requestedOriginal pair, selected pair, forwarded pair, response model (if supplied), host-effective effort (if supplied), status, source snapshot hashes, exclusion reasons, estimate/reservation/observed token buckets/cost source. “Requested effort” unless host confirms effective field; provider response not proving internal effort. Log no reasoning/private prompts/tool contents/secrets. Short inspectable reason codes plus plain text explanation; default no transcript spam. Defaults 1000 retained events/session,20 sessions or 30days, whichever expires first; local cleanup within mod's own state path only.
