# Routing policy

The heuristic optimizes a comparable model/effort cohort. It does not establish that a model is best at an arbitrary individual task.

1. Respect manual hold, settings/environment pins, account backend and confirmed IDs. Keep native settings if any required evidence or current input-token count is unknown. Aliases that do not map to an exact known runtime model retain native settings.
2. Join AA variants using exact slug identity or an explicit user-confirmed version/effort mapping. Effort support and context/output limits come from runtime capability flags. Missing capabilities, unmatched/new identities and unspecified benchmark effort on an effort-capable model are excluded.
3. Select general/coding/agentic-coding or a domain index from the local task classifier or current-intent override. Math uses general intelligence as a documented proxy. No available task index means no switch. Only the same reported AA major.minor methodology version is compared. AA does not expose methodology patch version here.
4. Require sufficient input context capacity and matching thinking-capability profiles with the baseline. Risky, complex, ambiguous and twice-failing intents retain baseline raw task score and never reduce effort. More than 72-hour-old data follows the same quality restriction. More than seven-day-old data stops switching.
5. Compute average-rank cohort percentile; ties retain their average rank and highest-score ties are always admitted. Apply the chosen mode's floor. Sports also requires 97% of the cohort's strongest raw score when the score is positive. This is an index-distance heuristic, not a success-probability or quality guarantee.
6. Forecast input at the higher known input/cache-write unit price plus the model's discovered maximum output budget at AA prices. Normalize cost and latency within the eligible cohort; missing values remove the corresponding dimension for everyone. Rank by weighted utility, then current pair, lower forecast cost, lower benchmark latency and stable ID.
7. Standard tasks cannot fall more than 0.10 below the baseline cohort percentile. Model hysteresis normally waits two steps. A lower-score winner must pay back conservatively over five equal-context requests by at least 5%; unknown costs prevent that downgrade. Treating every candidate request as uncached avoids assuming an unavailable cache hit. It does not predict all actual provider cache charges.
8. Changed requests on a confirmed direct API backend require explicit APEX credit consent. When consent is enabled, reserve the upper forecast before dispatch against the configured API-equivalent routing budget. Unknown observed costs retain their reservation. Budget exhaustion preserves native settings; it never claims to stop all account charges.

The receipt stores mode, revision, original/requested pair, task/risk, reason, top ten ranked comparisons, response-reported model and observed token cost when all needed prices are known. Rejected runtime models are excluded for the current joined catalogue; a later verified refresh can rebuild it. No automatic retry is performed by APEX.

AA's benchmark USD/task is the average cost of its Intelligence Index evaluation, not the predicted cost of your prompt. Request forecasts and observed API equivalents are separate. No subscription usage percentage or actual credit balance is fabricated.

Quality once changes only the captured preference for the next main dispatch. It preserves base mode and follows all steps above, including hysteresis, consent and budget checks. Consumption is atomic before forwarding; agents cannot claim it. A main dispatch consumes it even when a guard holds native settings. Restart/clear cancels an unused token. Receipts freeze the exact baseline/selected evidence, prices, methodology and fetch time; refresh cannot alter a historical explanation.
